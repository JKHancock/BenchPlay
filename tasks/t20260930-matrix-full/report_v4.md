**模型结构树（print(model) 等效，由 M0 权重文件逐名推导）：**
```python
# ── 模型结构: 每行注释说明该组件做什么、对推理性能/能力的影响 ──
Qwen3_5ForCausalLM(  # 顶层: 条件生成(支持文+图输入)
  (model): Qwen3_5Model(
    (embed_tokens): Embedding(152064, 4096)  # 词嵌入: 152064个token→4096维向量; 词表越大中文/代码覆盖越好
    (layers): ModuleList(
      (0-63): 64 x DecoderLayer(  # 64层堆叠; 每层=注意力+FFN+归一化
        (self_attn): Attention(  # 标准自注意力: 每个token'看'所有前文
          (q_proj): Linear(4096, 4096)  # Query: 32个头, 每个128维; 决定'我在找什么'
          (k_proj): Linear(4096, 512)  # Key: 仅4个KV头(GQA)→KV缓存缩小8倍
          (v_proj): Linear(4096, 512)  # Value: 同KV头数; 存'我找到了什么'
          (o_proj): Linear(4096, 4096)  # 输出: 拼接所有头的结果投影回去
          (rotary_emb): RotaryEmbedding()  # 位置编码: 让模型知道token的先后顺序
        )  # ← 复杂度O(n²); KV头越少, 推理时能缓存的上下文越多
        (mlp): MLP(  # 稠密FFN: 所有参数都参与计算
          (gate_proj): Linear(4096, 16384)  # 升维×4: SwiGLU gate分支
          (up_proj): Linear(4096, 16384)  # 升维×4: SwiGLU up分支
          (down_proj): Linear(16384, 4096)  # 降维回隐藏维
          (activation): SiLU()  # 激活函数: x·sigmoid(x)
        )  # ← 每 token 读全量FFN权重; 稠密模型速度受限于显存带宽÷权重GB
        (input_layernorm): RMSNorm()  # 注意力前归一化: 稳定数值分布
        (post_attention_layernorm): RMSNorm()  # FFN前归一化
      )
    )
    (norm): RMSNorm()  # 最终层归一化
  )
  (lm_head): Linear(4096, 152064, bias=False)  # 输出层: 隐藏向量→152064个token的概率分布
)
#
# 总参数: ~27B | 权重: 15.5GB (NVFP4=4bit浮点+两级缩放)
# 层数: 64 | 隐藏维: 4096 | 注意力: 32头(查询)/4头(KV缓存) | 词表: 152064
```

本报告使用以下评测体系，每个数字的含义如下：

### 性能指标

| 指标 | 含义 | 如何测量 | 分数说明 |
|---|---|---|---|
| TTFT (首字延迟) | 用户发出请求到收到第一个字的等待时间 | 逐请求毫秒级计时 | p50=一半请求比这快; <500ms 体感秒回
| TPOT (每token耗时) | 流式输出中相邻两个字的间隔 | 总生成时间÷token数 | p50 越低打字机越流畅; <100ms 阅读无卡顿
| ITL (token间延迟) | 任意两个字之间的最坏间隔 | 逐 chunk 时间戳差 | p99 越小=没有突然卡顿
| 出流 tok/s | 所有用户加起来每秒产出多少字 | 总输出token÷总耗时 | 越高能同时服务的人越多
| goodput | 同时满足 TTFT≤500ms 且 TPOT≤100ms 的请求占比 | 逐请求判定 | 100%=全部秒回; <50%=一半人体感差
